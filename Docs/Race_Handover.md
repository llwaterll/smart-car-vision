# NEUQ 校赛 vision1.2 联调交接

本版对应 STM32F407VE、双驱动轮差速底盘、香橙派和 640×480 摄像头，已合入本次提供的 vision1.2.rar 数独模块并完成运行入口对接。车载三级菜单使用 PE10 上、PE8 下、PE7 确认、PE9 返回。运行或故障状态下 PE10 优先停车并清最近故障码；每个故障码的历史记录在 `Sensors → 故障记录`，OK 清空且不停车。当前记录模式下故障不会停车，也不会降速，按目标轮速全速运行；把 `CAR_FAULT_DERATE_PERCENT` 改为 10 可恢复 10% 降额。原蓝牙调试台仍可在手动模式下单独调轮速。后续编译使用本工程源码。

## 下载、接线与发车

1. 将按本车参数编译的 HEX 烧入 F407。香橙派 3.3 V TTL TX 接 F407 PC11，香橙派 RX 接 F407 PC10，共地，115200 8N1（UART4）。按编码器接线图，红、白接电机驱动器的两路电机输出，蓝接编码器 3.3 V，黑接共地。黄线为 A 相，绿线为 B 相，左轮依次接 TIM4 的 PB6/PB7，右轮依次接 TIM3 的 PA6/PA7。保持 Flash 片选 PB0 为高。LCD 独占 SPI3。本车选用 MPU6050，I²C3 的 SCL 接 PA8、SDA 接 PC9，固件使用 7 位地址 0x68。蓝牙独占 USART1（PA9 TX / PA10 RX，9600 8N1）。
2. 固定相机和轮胎，在板上进入 `vision_inspection/vision`。以实际设备名替换下方示例的 `/dev/ttyS1`。先给 F407 上电，保持车体静止，再运行发送器。MPU6050 初始化后至少需要约 1 秒静止时间来采集 100 个有效样本并估计零偏。

   ```bash
   bash build.sh vision
   ./vision --camera 0 --config track_frontend.yml --vision-uart /dev/ttyS1 --publish-curvature
   ```

   vision1.4 默认自动握手：先等 F407 的 STATUS，看到 `STOP + ALLOW_HELLO +
   !FINISH_PENDING` 才生成新 session 并发 HELLO，未绑定前每 300 ms 重试。
   只有 PC10 -> 香橙派 RX 的反向线接好，自动握手才可用；没有反向线时临时
   使用 `--legacy-hello`，并人工确认 F407 在 STOP。`--publish-curvature`
   是发车前提，否则 F407 永远显示“无有效曲率”。

3. 相机看到起点的有效道路后，在屏幕选择 `Race → Start race`，进入第三级确认页。
   第 3 行显示“视觉: 已开启”、第 4 行不再等待握手后，按 PE7 发车；视觉未就绪时
   按 OK 会进入“预备”，自动握手完成后开跑。只有车轮静止、处于 STOP、会话已绑定、
   有新鲜且实测有效的道路曲率、元素为 0 时才能启动；单边估计 bit4 不能发车。
   条件不满足时屏幕显示具体原因。比赛中由车载程序执行动作，蓝牙驾驶帧不参与控制。
   按 PE10 在下一次 5 ms 控制处理时撤去驱动并清最近故障码（故障历史保留）；整个停车按键动作会被消耗，
   松开后才恢复菜单导航。重新比赛时先停车即可：F407 结束上一轮后自动关闭会话，
   图像端会换新 session 重绑，不需要重启视觉程序；旧数独块随会话清空。
4. 终点停车后 LCD 自动进入数独结果页。两轮低于 2 rpm 连续 100 ms 后，控制端收集当前会话的四块快照；缺块时最多等到终点触发后 1 秒，接收正在传输的末帧。之后冻结题面并求解，成功时显示六行六列答案；缺块、矛盾或无解、多解、搜索预算耗尽分别显示原因。收尾期间保持停车并拒绝新 HELLO 会话。结果可从菜单重新查看，新会话清除上一轮结果。本地录像可使用 `--video recording.avi --output new-directory --save-every 10` 回放并检查 CSV、掩膜、边线和鸟瞰图。

## 车载三级菜单与调车

按键消抖和 LCD 逐字符刷新移植自 [task2 分支 f91e29c](https://github.com/another-bbzj/smart_car_test/tree/f91e29cfbe56f9732607ae05b636d19826e9ae83/CODE)。四键均低电平有效，每 10 ms 扫描，连续 30 ms 确认按下或松开。上下键按住 500 ms 后每 100 ms 连发，确认和返回每次按下只生效一次。

| 一级入口 | 二级选项 | 第三级页面与操作 |
|---|---|---|
| Race | Start race | 显示发车条件，Ready 后按 OK 启动 |
| Race | Race status | 比赛阶段、圈数、累计里程、比赛融合航向、已收子块数量 |
| Race | Sudoku result | 途中显示四块接收进度，终点显示答案或具体失败原因 |
| Sensors | Wheel speeds | 左右轮参考转速、实测 rpm、PWM 百分比 |
| Sensors | IMU / MPU6050 | 可用状态、100 点校零进度、Z 轴零偏、校正后 Z 轴角速度 |
| Sensors | Vision | 新鲜帧的会话、帧号、置信度、有效曲率和赛道元素 |
| Left wheel PID | Kp / Ki / Kd | 显示当前值和候选值，上下修改，OK 应用，BACK 取消 |
| Right wheel PID | Kp / Ki / Kd | 同上，作用于右轮 |
| 左/右轮 PID | Save parameters | 停车后手动保存两轮全部六项已生效参数，重启自动加载 |

PID 单击步长 0.01，长按连发步长 0.10，允许范围 0–655.35。应用时沿用蓝牙调参的 STOP 状态校验和控制器初始化，只有选中的一项增益改变。参数先应用于 RAM，调好后在任一 PID 子菜单进入 `Save parameters` 并确认，一次保存两轮参数；上电优先加载有效保存记录，无有效记录才使用 `Board_Config.h` 默认值。详见 [PID 掉电保存](PID_Storage.md)。调车时先停车设置 PID，再通过已有蓝牙调试台逐轮试转，屏幕与蓝牙遥测均可核对反馈。屏幕底部显示整车状态和最近故障码；`Sensors → 故障记录` 显示每个故障码的次数和最近发生时间，UP/DOWN 翻页。

MPU6050 页显示的角速度单位为 °/s，来自比赛实际使用的 Z 轴读数。校零未完成时显示进度，超过 40 ms 的旧角速度隐藏。比赛航向只随比赛控制更新。IMU 初始化或读取失败时由双轮编码器提供比赛航向，页面显示传感器不可用或数据过期。

菜单状态和按键事件在控制节拍内处理，LCD 在主循环按行分次绘制。蓝牙发送每次最多推进 4 字节，使主循环能及时服务陀螺仪和屏幕。当前使用 ASCII 英文标签以适配板载字库。

## 各赛项实际执行位置

| 赛项 | 软件行为 | 实车验收 |
|---|---|---|
| 整圈、环岛和十字 | 香橙派按白色 PVC 和蓝底提取边线。普通赛道优先取同一预瞄高度的双边界中点，单边、环岛、十字沿用对应选线器。F407 用曲率计算角速度并换成左右轮 rpm。第一圈按菜单转速全速（默认 300 rpm≈1.02 m/s），第二圈保留原比例上限；曲率、置信度、元素和终点减速已关闭。 | 在直线左右偏置发车，检查两种偏差均能回中。保存环岛进、绕、出及十字每个分支的录像，核对实际行进方向。蓝锥桶依靠边界跟踪和车身净空通过，当前没有独立锥桶定位器。 |
| 160 cm 断路 | 蓝底近端丢失白路产生候选。底盘检查进场条件，用两轮里程和航向保持穿越；有新鲜陀螺数据时融合角速度。走过至少 1.30 m 后须连续三张不同帧确认白路；超过 1.95 m 或 12.5 s 未恢复会停车。 | 填写进场窗口，核查实车前轴到缺口、摄像头先看到远端白路的距离。分别测试正确接回、遮镜、错误位置丢线和中途断串口。 |
| 绿、黄、红路障 | 绿色保持巡线。黄色由稳定检测及鸟瞰距离触发，底盘按实测位移和航向先侧移，再回到车道。红色第一圈通过，第二圈在近端停车，两轮反馈低于 2 rpm 后连续计满 5 秒再起步。 | 逐色测检测距离、制动距离、黄障最近轮胎及车身净空。核对两圈各一次触发和障碍离开后的重新使能。 |
| 数独 | 香橙派以 Tag36h11 的 0/1、2/3、4/5、6/7 配对确定子块，使用网格边框透视矫正和 vision1.2 模板识别。每块连续两次一致才发送，单帧多块分别发送 TYPE=2。F407 缓存原始四块，在终点按 2×3 宫规则检查唯一解并上屏。 | 相机要能同时拍全一块的两个标签与网格外框。用赛场印刷字体、运动模糊、斜拍、阴影和空格样片验收；识别依赖字形模板，保留疑难样片。 |
| 现场盲盒和真正停车点 | 当前以累计里程计圈，练习终点设在两圈。现场若以地标停车或要求特殊动作，按公布条件更新任务和测试。 | 记录裁判公布的触发条件、动作、结束条件和允许误差，写入下表后再作现场验收。 |

道路几何在串口采用向左为正。视觉端在鸟瞰像素转米后统一转换符号。F407 以 5 ms 周期读取编码器，用当前视觉帧的曲率计算目标轮速，双轮同比限幅并用有界加速度跟踪移动目标。手动驾驶继续使用原五次参考曲线。转速内环保留测量微分滤波、抗积分饱和及可选前馈。MPU6050 在前台读取，PIT 只读快照；读失败或超过 40 ms 自动采用轮式航向。摄像头断流超过观测寿命或单帧丢线时不再直接停车：状态机沿用最近有效曲率并按当前目标速度继续行驶（当前全速模式不再降到 0.18 m/s），LCD 状态栏提示 `VISION LOST`；`RACE_VISION_LOST_STOP_MS`（默认 0）可恢复有界失效停车。断路阶段仍按里程和航向盲走，接回白路须连续三帧确认。算法背景见 [CMU Pure Pursuit 技术报告](https://www.ri.cmu.edu/publications/implementation-of-the-pure-pursuit-path-tracking-algorithm/)。

## 验收证据的范围

本机测试使用包内合成图、15 帧录像、生成的四组 Tag 网格、Linux 伪串口和差速运动学仿真。仿真将轮速目标转换为编码器位移，分别覆盖两圈断路、绕黄、红障停车和终点，未模拟轮胎侧滑、真实电机响应、底盘惯性或比赛现场光照。Keil 产物可用于烧录。本次没有烧写或操作实车；验收时请把第一圈时间、两次断路末端误差、近期转向录像、停车时长、LCD 照片和盲盒结果附在本文件旁。
